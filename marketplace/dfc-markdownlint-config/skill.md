# Markdown Lint With markdownlint-cli2

**One-line description:** Configures markdownlint-cli2 for a repository's Markdown files in a single `.markdownlint-cli2.jsonc`, decides each rule from a fixed table instead of disabling rules to get a clean run, and fixes violations one rule at a time until the lint exits 0.

**Execution Pattern:** Phase Pipeline

---

## Inputs

- `repo_path` (string, required): Absolute path to the repository root.
- `readme_path` (string, required): Path to the README from `dfc-readme-structure`; it is always inside the lint globs.

---

## Outputs

- `markdownlint_config` (string): Path to `.markdownlint-cli2.jsonc` at the repository root, with every rule change commented with its reason.
- `markdownlint_report` (object[]): Final lint result per rule: rule ID, count before, count after, action taken (fixed, configured, inline-disabled with file and line).

---

## Phase 1: Baseline Run

### Entry Criteria
- Node.js is installed: `node --version` prints a version.
- `repo_path` contains at least one `.md` file.

### Actions
1. Check for existing config files, because markdownlint-cli2 reads several and you must not create a second competing one: `ls -a <repo_path> | grep -E '^\.markdownlint'`. Recognized names include `.markdownlint-cli2.jsonc`, `.markdownlint-cli2.yaml`, `.markdownlint.jsonc`, `.markdownlint.json`, `.markdownlint.yaml`.
2. If a config exists, edit that file in Phase 2 instead of creating a new one.
3. Run the baseline over tracked Markdown, excluding dependencies: `npx markdownlint-cli2 "**/*.md" "#node_modules" "#.venv" "#target" "#vendor"`. The `#` prefix negates a glob.
4. Count violations by rule: pipe the output through `grep -o -E 'MD[0-9]{3}/[a-z-]+' | sort | uniq -c | sort -rn`.
5. Read each output line as `<file>:<line>[:<column>] <rule-id>/<rule-alias> <description> [<detail>]`, for example `README.md:41:81 MD013/line-length Line length [Expected: 80; Actual: 117]`.

### Output
Baseline counts per rule.

### Quality Gate
- The baseline command ran and its per-rule counts are recorded (zero counts are valid).

---

## Phase 2: Decide Each Rule From a Table

### Entry Criteria
- Baseline counts recorded.

### Actions
1. Decide every rule that fired using this table. Do not decide by "too many violations, turn it off":

   | Rule | Default | Decision |
   |---|---|---|
   | MD013 line-length | 80 characters | If the repo wraps prose by sentence or not at all, set `"MD013": false` with comment "prose is not hard-wrapped"; tables and code blocks are already handled by the `tables` and `code_blocks` options. If the repo hard-wraps, keep it on. |
   | MD033 no-inline-html | on | If the docs site needs HTML (`<details>`, `<img width>`), set `"MD033": {"allowed_elements": [<the elements actually used>]}`; list only elements found by `grep -rhoE '<[a-z]+' --include='*.md' . \| sort -u`. |
   | MD041 first-line-heading | on | Keep on. If files begin with front matter, markdownlint already skips it. |
   | MD024 no-duplicate-heading | on | Set `{"siblings_only": true}` for changelogs with repeated "Added"/"Fixed" headings. |
   | MD040 fenced-code-language | on | Keep on; fix by adding a language (`bash`, `text`, `python`, `json`). |
   | MD046 code-block-style | consistent | Set `{"style": "fenced"}`. |
   | Any other rule | default | Fix the files; do not configure. |

2. Write the config with comments (JSONC allows `//` comments):
   ```jsonc
   {
     "config": {
       "default": true,
       // prose is not hard-wrapped in this repo
       "MD013": false,
       "MD046": { "style": "fenced" }
     },
     "globs": ["**/*.md"],
     "ignores": ["node_modules/**", ".venv/**", "target/**", "vendor/**", "CHANGELOG.md"]
   }
   ```
   Only put `CHANGELOG.md` in `ignores` when it is generated by a tool (for example release-please or changesets).
3. Do NOT use `"default": false`; that turns off every rule.

### Output
`markdownlint_config` written.

### Quality Gate
- `node -e "require('fs').readFileSync('.markdownlint-cli2.jsonc','utf8')"` exits 0 and `npx markdownlint-cli2` (no globs; it reads `globs` from the config) runs without a config parse error.
- Every rule set to `false` or given options has a `//` comment on the line above it.

---

## Phase 3: Fix Violations Rule by Rule

### Entry Criteria
- Config written.

### Actions
1. Run the auto-fixer first: `npx markdownlint-cli2 --fix`. It fixes rules that have safe fixes (for example MD009 trailing spaces, MD012 multiple blank lines, MD047 final newline) and leaves others.
2. Review the change: `git diff --stat` then `git diff` for one file. If `--fix` changed content inside code blocks in a way that alters a command, revert that hunk with `git checkout -p <file>`.
3. Fix the remaining rules by hand, one rule ID at a time across all files, rerunning `npx markdownlint-cli2` after each rule. Do NOT fix several rules in one pass.
4. For a single justified exception, use an inline comment on the line above: `<!-- markdownlint-disable-next-line MD033 -->`. Record file and line in `markdownlint_report`.

### Output
`markdownlint_report` with before and after counts.

### Quality Gate
- `npx markdownlint-cli2; echo $?` prints `0` as the last line.
- `git grep -n 'markdownlint-disable' -- '*.md' | wc -l` equals the number of inline-disabled rows in `markdownlint_report`.

## Worked Example

Illustrative only. Baseline:
```
$ npx markdownlint-cli2 "**/*.md" "#node_modules"
Summary: 23 error(s)
README.md:1 MD041/first-line-heading/first-line-h1 First line in a file should be a top-level heading [Context: "[![CI]..."]
docs/usage.md:14 MD040/fenced-code-language Fenced code blocks should have a language specified [Context: "```"]
...
$ ... | grep -o -E 'MD[0-9]{3}/[a-z-]+' | sort | uniq -c | sort -rn
  14 MD013/line-length
   6 MD040/fenced-code-language
   2 MD009/no-trailing-spaces
   1 MD041/first-line-heading
```
Phase 2: repo does not hard-wrap prose, so MD013 is set to `false` with a comment. Phase 3: `--fix` clears MD009; MD040 is fixed by adding `text` and `bash` to six fences; MD041 is fixed by moving the badge line below the `# tidyconf` heading. Final run prints `Summary: 0 error(s)`.

---

## Exit Criteria

DONE when one markdownlint-cli2 config exists with a reason comment on every changed rule, and `npx markdownlint-cli2` exits 0 with each inline disable listed in `markdownlint_report`.

---

## Error Handling

| Phase | Failure Mode | Response |
|---|---|---|
| Phase 1 | `npx` cannot reach the registry | **Retry**: once; then **Stop** and report that the lint needs `npm install --save-dev markdownlint-cli2` from a reachable registry. |
| Phase 1 | Two config files already exist | **Adjust**: keep the `.markdownlint-cli2.*` file, move rules from the other into it, and report the duplicate for the user to delete. Never delete it yourself. |
| Phase 2 | A rule not in the table fires hundreds of times | **Adjust**: fix it with `--fix` if fixable; otherwise fix one directory per run. Do not disable it. |
| Phase 3 | `--fix` rewrites generated files | **Adjust**: add the generated path to `ignores` and revert those files with `git checkout -- <path>`. |
