# Matrix Maintenance Cadence

Set up a cadence to maintain the matrix. Skills change as the work changes. People learn new skills. New people join. People leave. A matrix that is 6 months old is unreliable. Update quarterly: reassess proficiency levels, add new skills from recent work, remove skills no longer needed, and re-scan for new single points of failure.

## Inputs

- `hiring-priorities`: Current hiring needs from the matrix
- `hire-vs-train-decision`: Whether each gap is addressed by hiring or training

## Outputs

- `maintenance-schedule`: Quarterly cadence for updating the matrix: who does it, what they review, and how results are communicated to the team
- `change-trigger-list`: Events that should trigger an immediate matrix update outside the quarterly cadence (e.g., someone leaving, a new project with new skill requirements, a reorg)

## Process

1. Schedule a quarterly matrix review. The team lead or manager runs it. Each review takes 1-2 hours.
2. In each review: ask the team what new tasks they performed this quarter that required new skills. Add those skills. Remove skills the team no longer needs.
3. Reassess proficiency levels for any person who has been cross-training or has taken on new responsibilities.
4. Re-scan for single points of failure and update the cross-training and hiring priorities.
5. Define the triggers for out-of-cycle updates: someone gives notice, a new project is staffed, a reorg moves people in or out.
