# Stressor Design Protocol

Design small, frequent stressors that strengthen the system without breaking it. Progressive overload for systems.

## Inputs

- `fragile-components`: The fragile components to strengthen
- `fragility-assessment`: The full assessment

## Outputs

- `stressor-schedule`: A schedule of designed stressors: what, when, how intense, and what adaptation is expected from each
- `dose-response-limits`: For each stressor: the maximum safe intensity (stress that strengthens vs. stress that breaks)

## Process

1. For each fragile component, design a stressor that is small enough to survive but large enough to trigger adaptation. Examples: for a team, simulate a key person's absence for a day. For a business, stress-test the cash flow with a simulated revenue drop. For health, increase exercise intensity gradually.
2. Set the frequency: stressors need to be frequent enough for adaptation but spaced enough for recovery. Weekly for small stressors, monthly for larger ones, quarterly for simulated crises.
3. Define the dose-response limits: at what intensity does the stressor stop strengthening and start breaking? For a business, a simulated 10% revenue drop builds resilience; a real 50% drop may break it.
4. Schedule the stressors into the calendar. Stressors that are not scheduled do not happen.
