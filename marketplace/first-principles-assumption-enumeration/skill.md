# First Principles Assumption Enumeration

List every assumption baked into the current approach. You cannot question an assumption you have not named, so the goal here is completeness, not judgment.

## Inputs

- `problem-statement`: The problem restated with no solution assumed
- `solution-free-framing`: The core need expressed as a requirement

## Outputs

- `assumption-list`: Every assumption behind the current approach, one per line
- `assumption-count`: How many distinct assumptions were surfaced

## Process

1. For the current approach, ask what has to be true for this to make sense and write each answer down.
2. Cover cost, time, materials, rules, customer behavior, and technical limits. Each is a source of hidden assumptions.
3. Phrase each assumption as a claim that could be true or false, not as a vague worry.
4. Do not judge any assumption yet. Capture first, test later.
5. Count the distinct assumptions so the next step has a clear list to work through.
