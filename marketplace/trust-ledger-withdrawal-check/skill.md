# Trust Ledger Withdrawal Check

Create the pre-withdrawal check, the core payoff of the ledger: a short protocol you run before any favor, hard conversation, or request, so that you draw on healthy accounts and shore up thin ones before drawing rather than after causing damage.

## Inputs

- `deposit-plans`: The deposit plans for low accounts
- `deposit-schedule`: The timing of planned deposits

## Outputs

- `withdrawal-checklist`: The short checklist to run before any withdrawal: current balance, size of the withdrawal, whether to deposit first or proceed
- `withdrawal-timing-rules`: Rules for when to delay a withdrawal to build balance first and when the withdrawal cannot wait

## Process

1. Write the checklist as three questions: what is the current balance in this account, how large is the withdrawal I am about to make, and does the balance comfortably cover it?
2. Set the decision rule. Healthy balance and small withdrawal: proceed. Thin balance or large withdrawal: deposit first if you can, or at minimum acknowledge the draw (name that you are asking a lot). Overdrawn: do not withdraw unless it is unavoidable.
3. Add timing rules for the unavoidable case. Some withdrawals cannot wait (urgent bad news, a time-boxed request). When you must withdraw from a low account, pair it with an immediate sincere acknowledgment and a concrete plan to rebuild, so the draw does not read as careless.
4. Make the check a habit by attaching it to a trigger: before sending a request, before a performance conversation, before asking a vendor for an exception. The check is worthless if you only remember it after the relationship is already strained.
