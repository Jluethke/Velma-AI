# Pain Driven Addition Protocol

Run the minimal process and add steps back ONLY when specific pain appears (a defect, a failure, a rework cycle).

## Inputs

- `essential-steps`: The minimal process
- `removed-steps`: Steps that were removed

## Outputs

- `pain-log`: Record of problems that occurred during the minimal process trial, each with the date, impact, and whether adding a step would have prevented it
- `added-back-steps`: Steps added back to the process because specific pain proved they were necessary

## Process

1. Run the minimal process for 2-4 weeks. Track every problem that occurs.
2. For each problem, ask: would a process step have prevented this? If yes, add that specific step. If not (the problem was a one-time event or an external factor), do not add a step.
3. The key discipline: only add a step when pain proves it is needed, not when fear suggests it might be needed. Fear-driven process steps are the source of most process bloat.
4. Each added step must specify: what triggers it, who does it, what the output is, and what problem it prevents. A step without a clear purpose will be skipped.
