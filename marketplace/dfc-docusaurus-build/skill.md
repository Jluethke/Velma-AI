# Docusaurus Site Build With Broken Link Enforcement

**One-line description:** Builds a Docusaurus 3 docs site with a sidebar grouped by Diataxis type from the doc plan, Mermaid through `@docusaurus/theme-mermaid`, broken links and anchors set to fail the build, and MDX 3 compile errors fixed by cause, until `npm run build` exits 0.

**Execution Pattern:** Phase Pipeline

---

## Inputs

- `repo_path` (string, required): Absolute path to the repository root.
- `doc_plan` (object[], required): Page plan from `dfc-audience-doctype-plan`; Diataxis types become sidebar categories.

---

## Outputs

- `site_dir` (string): Built site directory (Docusaurus default `build/` inside the site folder).
- `site_build_log` (object[]): Build errors and warnings by kind before and after, with the fix for each.

---

## Phase 1: Scaffold or Locate the Site

### Entry Criteria
- `node --version` prints a version that the installed Docusaurus release supports (check the `engines.node` field of `@docusaurus/core` with `npm view @docusaurus/core engines`).

### Actions
1. Find an existing site: `ls docusaurus.config.* website/docusaurus.config.* docs-site/docusaurus.config.* 2>/dev/null`. If found, use it and skip step 2.
2. Scaffold: `npx create-docusaurus@latest website classic --typescript`. It creates `website/` with `docusaurus.config.ts`, `sidebars.ts` and `docs/`.
3. Read the version: `npm ls @docusaurus/core --prefix website`. This flow targets Docusaurus 3 (MDX 3). For version 2, check the v2 docs for each config key named here.

### Output
Site directory and version.

### Quality Gate
- `npm run build --prefix website` runs (pass or fail) and prints Docusaurus build output, proving the site is wired.

---

## Phase 2: Configure Sidebar, Mermaid and Link Policy

### Entry Criteria
- Site located.

### Actions
1. In `docusaurus.config.ts` set:
   ```ts
   const config: Config = {
     title: 'durationkit',
     url: 'https://acme.github.io',
     baseUrl: '/durationkit/',
     onBrokenLinks: 'throw',
     onBrokenAnchors: 'throw',
     markdown: {
       mermaid: true,
       format: 'detect',
     },
     themes: ['@docusaurus/theme-mermaid'],
     // presets: keep the classic preset generated by the scaffold
   };
   ```
   Install the theme: `npm install --prefix website @docusaurus/theme-mermaid` at the same version as `@docusaurus/core`. `format: 'detect'` parses `.md` files as CommonMark and only `.mdx` files as MDX, which avoids MDX errors in plain Markdown pages. The setting for broken Markdown file links (`onBrokenMarkdownLinks`) moved under `markdown.hooks` in recent 3.x releases; set it to `'throw'` at the location the docs for your installed version give.
2. Write `sidebars.ts` with one category per Diataxis type in `doc_plan`:
   ```ts
   const sidebars: SidebarsConfig = {
     docs: [
       'intro',
       { type: 'category', label: 'Tutorial', items: ['tutorial/first-parse'] },
       { type: 'category', label: 'How-to guides', items: ['how-to/retry-config'] },
       { type: 'category', label: 'Reference', items: [{ type: 'autogenerated', dirName: 'reference' }] },
       { type: 'category', label: 'Explanation', items: ['explanation/architecture'] },
     ],
   };
   ```
   Doc IDs are paths under `docs/` without the extension (unless front matter sets `id`).
3. Do NOT set `onBrokenLinks` or `onBrokenAnchors` to `'warn'` or `'ignore'` to get a green build.

### Output
Configured site.

### Quality Gate
- `grep -n -E "onBrokenLinks: 'throw'|onBrokenAnchors: 'throw'" website/docusaurus.config.ts` prints two lines.
- Every doc ID in `sidebars.ts` exists as a file under `website/docs/`.

---

## Phase 3: Build and Fix

### Entry Criteria
- Configuration done.

### Actions
1. Build: `npm run build --prefix website 2>&1 | tee /tmp/docusaurus.log`.
2. Fix by message:

   | Message contains | Cause | Fix |
   |---|---|---|
   | `Docusaurus found broken links!` followed by `On source page path = ... -> linking to ...` | Link target route does not exist | Fix the link; prefer relative file links (`../reference/cli.md`) that Docusaurus resolves to routes |
   | `broken anchors` | Fragment does not match a heading ID | Use the generated heading slug or set an explicit `{#custom-id}` on the heading |
   | `MDX compilation failed` with `Could not parse expression with acorn` | A `{` in an `.mdx` page is read as a JS expression | Escape as `\{`, or put it in inline code or a code block |
   | `Expected a closing tag for <...>` | A `<` in `.mdx` text is read as JSX | Write `&lt;` or use inline code |
   | `Invalid sidebar file` / `These sidebar document ids do not exist` | Wrong doc ID | Fix the ID to the path under `docs/` |

3. Fix one message kind per rebuild.
4. Preview the production build: `npm run serve --prefix website`, open the printed URL, check Mermaid diagrams render.

### Output
`site_dir`; `site_build_log`.

### Quality Gate
- `npm run build --prefix website; echo $?` prints `0` last.
- `ls website/build/index.html` succeeds.
- `git check-ignore website/build` prints `website/build` (the scaffold's `.gitignore` includes it).

## Worked Example

Illustrative only. First build:
```
$ npm run build --prefix website
[ERROR] Error: Unable to build website for locale en.
[cause]: Error: MDX compilation failed for file "docs/reference/config.mdx"
Cause: Could not parse expression with acorn
Details: 14:22
[ERROR] Docusaurus found broken links!
- Broken link on source page path = /durationkit/docs/how-to/retry-config:
   -> linking to /durationkit/docs/reference/options
```
Fixes: line 14 had `{ "retries": 3 }` in prose, moved into inline code; the link pointed at a route renamed to `reference/config`, changed to the relative file link `../reference/config.mdx`. Rebuild: `[SUCCESS] Generated static files in "build".`

---

## Exit Criteria

DONE when the Docusaurus build exits 0 with broken links and anchors set to throw, the sidebar has one category per Diataxis type, and Mermaid renders in the served build.

---

## Error Handling

| Phase | Failure Mode | Response |
|---|---|---|
| Phase 1 | Node version below the release's `engines` | **Stop**: install a supported Node version (for example with `nvm install <version>`); do not downgrade Docusaurus silently. |
| Phase 2 | `@docusaurus/theme-mermaid` version mismatch error | **Adjust**: install the exact version printed by `npm ls @docusaurus/core`. |
| Phase 3 | Broken links point to generated API pages | **Adjust**: build the API reference first (`dfc-node-typedoc-reference` with the Markdown plugin) so the pages exist. |
| Phase 3 | Upgrade from v2 floods MDX errors | **Adjust**: keep `markdown.format: 'detect'` and fix `.mdx` files one at a time; Docusaurus provides an MDX checker (`npx docusaurus-mdx-checker`), confirm its name in the v3 upgrade guide. |
