# First Principles Problem Statement

State the problem precisely and strip out any assumed solution. Most problem statements smuggle in a preferred answer, which blocks original thinking before it starts.

## Inputs

- `problem-description`: The problem or goal, in the user's own words
- `current-approach`: How the problem is handled today, or the default industry approach
- `desired-outcome`: What a good result would actually look like

## Outputs

- `problem-statement`: The problem restated with no solution assumed
- `solution-free-framing`: The core need expressed as a requirement, not a method

## Process

1. Write the problem in one or two plain sentences a non-expert could follow.
2. Underline every word that names a specific solution or method rather than a need.
3. Rewrite the statement so it describes the need and the desired outcome only, with no method implied.
4. Confirm the restated problem still captures the real goal and nothing has been narrowed away.
