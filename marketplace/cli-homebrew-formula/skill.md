# CLI Homebrew Formula in a Tap

**One-line description:** Writes a Homebrew formula for the CLI in the user's own tap with the stack's build helper (`std_go_args`, `std_cargo_args`, `virtualenv_install_with_resources`, `std_npm_args`), generated shell completions and a real `test do` block, then passes `brew audit --strict`, `brew style`, a build-from-source install and `brew test`.

**Execution Pattern:** Phase Pipeline

---

## Inputs

- `tool_name` (string, required): Formula and executable name.
- `release_version` (string, required): Released version.
- `release_tarball_url` (string, required): URL of the source archive for that version (for example the GitHub tag archive or the PyPI/npm/crates sdist).
- `stack` (string, required): `python`, `node`, `go` or `rust`.
- `completion_scripts` (string[], required): From `cli-completion-generate`; tells whether the binary can print completions.
- `homebrew_tap` (string, optional): Tap name `ORG/tap` (repository `ORG/homebrew-tap`). Empty means skip this flow.

---

## Outputs

- `homebrew_formula` (string): Path of `Formula/<tool>.rb` in the tap.
- `brew_audit_log` (string): Output of audit, style, install and test.

---

## Phase 1: Tap and Checksum

### Entry Criteria
- `homebrew_tap` is not empty. Homebrew is installed (`brew --version`).
- The release tag and archive exist; the URL returns the archive (`curl -fsIL URL` shows `200`).

### Actions
1. Create the tap if it does not exist: `brew tap-new ORG/tap` (creates a local repo at `$(brew --repository)/Library/Taps/org/homebrew-tap` with CI workflow files). Push it to GitHub as `ORG/homebrew-tap`.
2. Compute the checksum of the exact archive: `curl -fsSL "$URL" | shasum -a 256`.
3. Start from the generator for the stack, which writes a skeleton you then edit: `brew create --tap ORG/tap --go "$URL"` (use `--rust`, `--python`, or `--node` per stack; run `brew create --help` to confirm the flags in your Homebrew version). Keep the class name Homebrew generates (CamelCase of the formula name).

### Output
Tap and skeleton formula with `sha256`.

### Quality Gate
- `shasum -a 256` output equals the `sha256` line in the formula.

---

## Phase 2: Install Block, Completions and Test

### Entry Criteria
- Skeleton formula exists.

### Actions
1. Write the install block for the stack:

| Stack | Dependencies | `def install` |
|---|---|---|
| go | `depends_on "go" => :build` | `system "go", "build", *std_go_args(ldflags: "-s -w -X main.version=#{version}"), "./cmd/logtrim"` |
| rust | `depends_on "rust" => :build` | `system "cargo", "install", *std_cargo_args` |
| python | `include Language::Python::Virtualenv` at class top, `depends_on "python@3.12"` (pick the version Homebrew core currently ships) | `virtualenv_install_with_resources`, with one `resource` block per dependency generated by `brew update-python-resources logtrim` |
| node | `depends_on "node"` | `system "npm", "install", *std_npm_args` then `bin.install_symlink libexec.glob("bin/*")` |

2. Completions, only if the binary prints them (`completion_scripts` came from the binary):
```ruby
generate_completions_from_executable(bin/"logtrim", "completion")
```
   This calls `logtrim completion bash|zsh|fish` and installs each output in Homebrew's completion directories. If the subcommand is named differently, pass that name; check `brew formula-cookbook` docs for the argument options (`shells:`, `shell_parameter_format:`).
3. Write a test that runs the real tool on real input, not only `--version`:
```ruby
test do
  assert_match version.to_s, shell_output("#{bin}/logtrim --version")
  (testpath/"a.log").write "2000-01-01T00:00:00Z INFO old\n"
  system bin/"logtrim", "trim", "--older-than", "24h", "--in-place", testpath/"a.log"
  assert_equal "", (testpath/"a.log").read
  shell_output("#{bin}/logtrim --bogus 2>&1", 2)   # expects exit status 2
end
```
   `shell_output(cmd, N)` fails the test unless the exit status is N.

### Output
Complete formula.

### Quality Gate
- The formula has `desc`, `homepage`, `url`, `sha256`, `license`, an `install` method and a `test do` block (read the file).

---

## Phase 3: Audit, Install, Test

### Entry Criteria
- Formula complete.

### Actions
1. Run in this order and save each output:
```
brew audit --strict --online ORG/tap/logtrim
brew style ORG/tap
brew install --build-from-source ORG/tap/logtrim
brew test ORG/tap/logtrim
brew uninstall logtrim
```
2. Fix every audit and style complaint in the formula; rerun from the top after each fix.
3. Commit `Formula/logtrim.rb` to the tap repository and push only with the user's approval. Users then run `brew install ORG/tap/logtrim`.
4. For later releases, `brew bump-formula-pr --url NEW_URL ORG/tap/logtrim` updates `url` and `sha256` (check its `--help` for tap support in your version), or edit both lines and rerun Phase 3.

### Output
`homebrew_formula`, `brew_audit_log`.

### Quality Gate
- `brew audit` and `brew style` print no offenses.
- `brew test` exits 0.

---

## Do Not

- Do not compute `sha256` from a locally built archive; it must match the downloaded URL byte for byte.
- Do not use `bottle :unneeded` or other removed DSL; `brew audit --strict` reports them.
- Do not submit to homebrew-core from this flow; core has its own notability and review rules.

## Worked Example

Illustrative. Go `logtrim` 1.4.0:
```
$ curl -fsSL https://github.com/acme/logtrim/archive/refs/tags/v1.4.0.tar.gz | shasum -a 256
3f1c...e9a2  -
$ brew audit --strict --online acme/tap/logtrim
acme/tap/logtrim
  * Description shouldn't start with the formula name.
Error: 1 problem in 1 formula detected.
```
Fix `desc "Trim old log lines and report counts"`, rerun:
```
$ brew install --build-from-source acme/tap/logtrim
==> go build -ldflags=-s -w -X main.version=1.4.0 ...
$ brew test acme/tap/logtrim
==> Testing acme/tap/logtrim
==> /opt/homebrew/Cellar/logtrim/1.4.0/bin/logtrim --version
```

---

## Exit Criteria

DONE when the tap formula passes strict audit and style, builds from source, its test exercises real behavior and an exit code, and completions install when the tool provides them.

---

## Error Handling

| Phase | Failure Mode | Response |
|---|---|---|
| Phase 1 | `homebrew_tap` empty | **Return**: skip this flow; report that Homebrew distribution was not requested. |
| Phase 1 | Checksum mismatch on install | **Retry**: recompute from the URL; a re-created tag changes the archive. |
| Phase 2 | Python resources missing | **Adjust**: run `brew update-python-resources`, then reinstall. |
| Phase 3 | `brew test` fails | **Stop**: fix the tool or the test input; never reduce the test to `--version` only. |
