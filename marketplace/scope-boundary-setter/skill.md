# Scope Boundary Setter

Define the scope boundary: what is included and, more importantly, what is explicitly excluded.

## Inputs

- `initiative-description`: What the project or initiative delivers
- `constraints`: The fixed constraints: deadline, budget, quality standard

## Outputs

- `in-scope-list`: Everything that is included, stated specifically enough that two people would agree on whether a given item is in scope
- `out-of-scope-list`: Everything explicitly excluded, especially items that someone might reasonably assume are included

## Process

1. List everything the project will deliver. Be specific: 'User login with email and password' not 'Authentication.'
2. List everything the project will NOT deliver, especially things that are adjacent to the deliverables. 'The project includes the API but NOT the mobile app that consumes it.' 'The report includes data from Q1-Q4 but NOT the predictive model.'
3. The out-of-scope list is more important than the in-scope list. Every scope dispute comes from something that was not explicitly excluded.
4. Get agreement on both lists from the key stakeholders before work begins. Written agreement, not verbal.
