# Daily Usage Logging

Use the product daily for real tasks and log every interaction: what worked, what did not, what was missing, what surprised you.

## Inputs

- `teardown-plan`: The 30-day test plan
- `use-case`: The real use case being executed

## Outputs

- `usage-log`: Daily log of interactions with the product: tasks attempted, time to complete, errors encountered, workarounds needed, features discovered, features missed
- `friction-inventory`: Running list of every friction point encountered during the 30 days

## Process

1. Use the product for at least 30 minutes per day on a real task. Not a tour of features, but actual work that produces actual output.
2. After each session, record: what you tried to do, how the product handled it, how long it took, where you got stuck, and what you wish the product did differently.
3. Note the features you discovered accidentally (undiscoverable features are a UX debt) and features you expected to exist but did not (feature gaps).
4. Track the cumulative friction: does the product get easier over time (good learning curve) or stay consistently frustrating (bad design)?
