# Action Verification At Next Retro

At the start of the next retrospective, verify the committed action was implemented and measure its effect. This creates accountability.

## Inputs

- `committed-action`: The action from the previous retrospective
- `success-criterion`: The measurable outcome to check

## Outputs

- `action-status`: Was the action implemented? If yes, did it produce the expected improvement? If no, why not?
- `improvement-trend`: The running log of retrospective actions and their outcomes, showing whether the team is actually improving over time

## Process

1. Start the retrospective by reviewing the previous action: was it implemented? Check with the owner.
2. If implemented, measure the success criterion: did the metric improve? Did the frustration recur? If the action worked, acknowledge it and move on.
3. If not implemented, ask why. Was it deprioritized? Was it harder than expected? Was the owner overloaded? The reason determines the response: re-commit, reassign, or redesign the action.
4. Maintain the improvement trend log: every retrospective action, its status, and its measured outcome. Over multiple sprints, this log shows whether retrospectives are producing real improvement or generating ignored lists.
