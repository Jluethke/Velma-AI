# CLI Reference Generated From the Argument Parser

**One-line description:** Generates the command-line reference page directly from the program's argument parser (click, argparse, Typer, cobra, clap, or captured `--help` for parsers without a generator) so every command, flag, default and environment variable in the docs comes from code, and adds a drift check that fails when the committed page differs from a fresh generation.

**Execution Pattern:** Phase Pipeline

---

## Inputs

- `repo_path` (string, required): Absolute path to the repository root.
- `doc_plan` (object[], required): Page plan from `dfc-audience-doctype-plan`; must contain a CLI reference row with source `code`.

---

## Outputs

- `cli_reference_path` (string): Path to the generated reference (for example `docs/reference/cli.md`) or the directive page that renders it at build time.
- `cli_drift_check` (string): The command that regenerates the reference and fails on any difference (`<generate> && git diff --exit-code <path>`), or "build-time" when the docs build renders from the parser directly.

---

## Phase 1: Identify the Parser Library

### Entry Criteria
- `doc_plan` has a CLI reference row.
- The CLI runs: `<tool> --help` exits 0.

### Actions
1. Find the parser with grep:

   | Grep (in source) | Library |
   |---|---|
   | `import click` / `@click.command` | click |
   | `import typer` | Typer |
   | `argparse.ArgumentParser` | argparse |
   | `github.com/spf13/cobra` in `go.mod` | cobra |
   | `clap` in `Cargo.toml` `[dependencies]` | clap |
   | `commander` or `yargs` in `package.json` | commander / yargs |

2. Find the entry object: the click group or command named in `[project.scripts]`, the function that builds the `ArgumentParser`, the cobra root `*cobra.Command`, the clap `#[derive(Parser)]` struct.
3. If the argparse parser is built inside `main()` and not returned by a function, a small refactor to `def build_parser() -> argparse.ArgumentParser` is needed for the generator to import it. Ask the user before changing code.

### Output
Library and entry object.

### Quality Gate
- The grep that identified the library prints at least one line, recorded with file and line.

---

## Phase 2: Generate the Reference

### Entry Criteria
- Library known.

### Actions
1. Use the generator for the library:

   | Library | Generator | How |
   |---|---|---|
   | click + Sphinx | `sphinx-click` | add `"sphinx_click"` to `extensions`; page contains `.. click:: tidyconf.cli:main` with options `:prog: tidyconf` and `:nested: full` |
   | click + MkDocs | `mkdocs-click` | add `mkdocs-click` to `markdown_extensions`; page contains a `::: mkdocs-click` block with `:module: tidyconf.cli` and `:command: main` |
   | argparse + Sphinx | `sphinx-argparse` | add `"sphinxarg.ext"` to `extensions`; page contains `.. argparse::` with `:module:`, `:func: build_parser`, `:prog:` |
   | Typer | Typer CLI | `typer tidyconf.cli utils docs --name tidyconf --output docs/reference/cli.md` (check `typer --help` for the installed version) |
   | cobra | `github.com/spf13/cobra/doc` | a small `cmd/gendocs/main.go` calling `doc.GenMarkdownTree(rootCmd, "docs/reference/cli")` |
   | clap | `clap-markdown` crate (Markdown) or `clap_mangen` (man pages) | a small binary or `xtask` that prints `clap_markdown::help_markdown::<Cli>()` into `docs/reference/cli.md` |
   | commander / yargs / other | none standard | a script that runs `<tool> --help` and `<tool> <sub> --help` for each subcommand and writes each output into a fenced `text` block under a heading |

2. Put a generated-file banner at the top of written files: `<!-- Generated by <command>. Do not edit by hand. -->`.
3. Install generators as dev dependencies and pin them (docs requirements, `go.mod` tool dependency, `[dev-dependencies]` or a separate `xtask` crate).
4. Do NOT hand-write or hand-edit any part of the generated reference. Missing help text is fixed in the parser's `help=` strings, cobra `Short`/`Long`, or clap doc comments, then regenerated.

### Output
`cli_reference_path`.

### Quality Gate
- For file generators: the generated file contains every subcommand printed by `<tool> --help` (`grep -c` per subcommand name is at least 1).
- For build-time directives: the docs site builds strictly (`mkdocs build --strict` or `sphinx-build -W -b html docs docs/_build/html`) and the built page lists every subcommand.

---

## Phase 3: Add the Drift Check

### Entry Criteria
- Reference generated.

### Actions
1. For generated files, define the drift command, for example: `go run ./cmd/gendocs && git diff --exit-code docs/reference/cli`. `git diff --exit-code` exits 1 when the regenerated file differs from the committed one.
2. For build-time directives (sphinx-click, mkdocs-click, sphinx-argparse), drift cannot happen; set `cli_drift_check` to "build-time".
3. Prove the check works: add a temporary flag in a scratch branch, run the drift command, confirm it exits 1, then discard the branch.

### Output
`cli_drift_check`.

### Quality Gate
- The drift command exits 0 on a clean tree and exits 1 after the temporary flag is added (both results recorded).

---

## Worked Example

Illustrative only. Go CLI using cobra.

Phase 1: `grep -n spf13/cobra go.mod` prints `5: github.com/spf13/cobra v1.8.0`; root command is `cmd.RootCmd` in `internal/cmd/root.go`.

Phase 2: `cmd/gendocs/main.go`:
```go
package main

import (
    "log"

    "github.com/acme/tidyconf/internal/cmd"
    "github.com/spf13/cobra/doc"
)

func main() {
    cmd.RootCmd.DisableAutoGenTag = true
    if err := doc.GenMarkdownTree(cmd.RootCmd, "docs/reference/cli"); err != nil {
        log.Fatal(err)
    }
}
```
`go run ./cmd/gendocs` writes `tidyconf.md`, `tidyconf_check.md`, `tidyconf_init.md`. `DisableAutoGenTag` removes the date footer, which would otherwise change on every run and break the drift check.

Phase 3:
```
$ go run ./cmd/gendocs && git diff --exit-code docs/reference/cli; echo $?
0
```
After adding a temporary `--verbose` flag: exit 1, diff shows the new flag row.

---

## Exit Criteria

DONE when the CLI reference is produced only from the parser, help-text gaps are fixed in code, and a drift check (or build-time rendering) keeps the page equal to the parser.

---

## Error Handling

| Phase | Failure Mode | Response |
|---|---|---|
| Phase 1 | Several parser libraries in one repo | **Adjust**: generate per tool; one reference page per binary. |
| Phase 2 | Generator output includes timestamps | **Adjust**: turn them off (cobra `DisableAutoGenTag`); otherwise strip them in the generation script before writing. |
| Phase 2 | User declines the `build_parser` refactor | **Adjust**: use the captured `--help` method for argparse and record it. |
| Phase 3 | Drift check passes after adding a flag | **Stop**: the check is not reading the generated path; fix the path before continuing. |
