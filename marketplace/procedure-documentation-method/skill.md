# Procedure Documentation Method

Document procedures using the test-first method: write the procedure, then have someone who has never done the task follow it. Every point where they get stuck or ask a question reveals a gap in the documentation.

## Inputs

- `expert-interview-protocol`: Method for extracting expertise
- `case-study-template`: Template for case studies

## Outputs

- `procedure-writing-guide`: Guide for writing procedures that pass the test-first method
- `documentation-priority-list`: Prioritized list of procedures to document, ordered by risk of knowledge loss

## Process

1. Write the procedure as the expert would explain it to a new person. Use numbered steps. Each step is one action. If a step contains the word 'and', split it into two steps.
2. Hand the procedure to someone who has never done the task. Watch them follow it without offering help. Every time they pause, ask a question, or make an error, mark that step as needing revision.
3. Revise the procedure to close every gap the test revealed. Then test again with a different person. Two clean runs means the procedure is ready.
4. Assign a freshness owner (not the author) and a review date based on how often the process changes.
