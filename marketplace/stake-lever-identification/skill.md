# Stake Lever Identification

For each stakeholder, identify the lever that would actually move their position: the evidence, assurance, accommodation, or trade that addresses their real interest. A lever is specific and grounded in their interest, not a generic case for why the outcome is good.

## Inputs

- `interest-map`: The underlying interests driving each position
- `stated-vs-real-interests`: Where stated reasons differ from real interests

## Outputs

- `movement-levers`: For each stakeholder, the specific thing that would move them toward support: evidence, an assurance, an accommodation, a trade, or a trusted endorsement
- `lever-evidence`: What you would need to supply or demonstrate for each lever to work

## Process

1. For each stakeholder, design the lever from their interest. If the interest is a protected workload, the lever is a credible assurance or a resource that protects it. If it is a metric, the lever is evidence the outcome improves or does not harm that metric.
2. Make levers specific to the person, not generic. The same project moves different stakeholders through different levers, and a one-size pitch persuades no one because it addresses no one's actual interest.
3. Prefer levers you can actually deliver. A lever that requires promising something you cannot guarantee buys short-term agreement and long-term distrust, so ground each lever in what you can genuinely provide.
4. Identify what each lever requires you to supply: the data to gather, the assurance to secure, the accommodation to arrange, or the trusted person whose endorsement would carry weight. The lever is only useful once you can actually pull it.
