# Problem Symptom Capture

State the recurring problem as an observable symptom with evidence of how often it happens. A symptom stated as a feeling or an opinion cannot be traced; a symptom stated as a countable event can.

## Inputs

- `recurring-problem`: The problem that keeps happening, in plain language
- `observation-context`: Where and when the problem shows up

## Outputs

- `symptom-statement`: The problem restated as one observable, countable event
- `occurrence-evidence`: How often the symptom occurred over a recent window

## Process

1. Rewrite the problem as a single observable event, not a judgment. Replace 'quality is bad' with 'three defects per hundred units reached the customer last month'.
2. Record how often the symptom happened over a recent, bounded window so later steps measure against a real rate.
3. Name where in the process the symptom first becomes visible, which is almost never where it is caused.
4. Confirm the symptom is specific enough that two people watching the same process would count it the same way.
