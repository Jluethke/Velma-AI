# SDK Typed Responses

**One-line description:** Makes every SDK method return a precise static type and decides, per stack, whether to validate responses at runtime (pydantic v2, zod, Go decoding), with forward compatibility for unknown fields and enum values, proven by strict type checking and negative type tests.

**Execution Pattern:** Phase Pipeline

---

## Inputs

- `type_mapping` (object, required): Output of `sdk-model-type-mapping`.
- `stack` (string, required): `python`, `typescript` or `go`.
- `project_dir` (string, required): SDK repository root.

---

## Outputs

- `response_validation` (object): Static type check command and result, runtime validation decision and library, unknown field and enum policy, and test results.

---

## Phase 1: Static Types Pass Strict Checking

### Entry Criteria
- Client code exists for the stack.

### Actions
1. Run the strict checker and record the error count:

| Stack | Command | Config |
|---|---|---|
| python | `mypy --strict acme_client` (or `pyright`) | Ship a `py.typed` marker file inside the package so callers' checkers read the types (PEP 561) |
| typescript | `npx tsc --noEmit` | `"strict": true`, `"noUncheckedIndexedAccess": true` recommended; `"declaration": true` for publishing |
| go | `go vet ./...` and `staticcheck ./...` | Types are enforced by the compiler |

2. Find untyped returns: python `grep -rnE "-> (dict|Any|object)\b" acme_client/`; typescript `grep -rnE ": (any|unknown)\b|Promise<any>" src/ --include=*.ts`; go `grep -rnE "interface\{\}|\bany\b" --include=*.go . | grep -v _test.go`.
3. For each hit on a public method, replace with the model type from `type_mapping`. Leave hits only where the spec itself is free-form, and record them.
4. Do NOT silence errors with `# type: ignore`, `as any`, or `//nolint` to reach zero. Each suppression must have a one-line reason comment and be recorded.

### Output
Static check results.

### Quality Gate
- The strict checker exits 0, or every remaining error is recorded with a reason.
- Every untyped public return left is backed by a free-form schema in the spec.

---

## Phase 2: Decide Runtime Validation

### Entry Criteria
- Static types pass.

### Actions
1. Apply this table:

| Stack and client | Runtime validation | Unknown fields | Unknown enum values |
|---|---|---|---|
| python, pydantic v2 models | Already validates on `model_validate` | `model_config = ConfigDict(extra="allow")` or `"ignore"`; never `"forbid"` on responses | Use `str` with known constants, or a validator that maps unknown values to a fallback; a strict `Enum` raises |
| typescript, openapi-typescript | None by default (types only) | Passed through | Typed as known union but may hold other strings at runtime |
| typescript, user wants runtime checks | zod schemas (generated by a tool the user approves, or handwritten), `schema.safeParse(data)`; use `.passthrough()` on objects to keep unknown keys | `.passthrough()` | `z.union([z.enum([...]), z.string()])` |
| go, `encoding/json` | Decoding checks JSON types only; missing fields become zero values | Ignored by default; do NOT use `Decoder.DisallowUnknownFields()` on responses | Named string type accepts any value; validate only if the method needs it |

2. Record the decision. If runtime validation is on, decide what a validation failure raises: a distinct `ResponseValidationError` (subclass of `AcmeError`) carrying the raw body, never a bare library exception.
3. Forward compatibility rule: a server adding a field or an enum value must not break existing SDK releases. Any configuration that rejects unknown fields or values on responses violates this rule.

### Output
Runtime validation decision.

### Quality Gate
- The decision row is recorded for the stack.
- `grep -rn "extra=\"forbid\"\|DisallowUnknownFields\|\.strict()" <src>` shows no use on response types.

---

## Phase 3: Prove It

### Entry Criteria
- Decision recorded.

### Actions
1. Negative static test: python a file under `tests/typing/` checked by mypy with `reveal_type` or an assignment that must fail, using `# type: ignore[assignment]` with `warn_unused_ignores = True` so an unused ignore fails; typescript `// @ts-expect-error` on accessing a property that does not exist on the returned model; go a compile-only test is not needed.
2. Forward compatibility runtime test: mock a response with an extra field and a new enum value; assert the call succeeds and known fields are correct.
3. If runtime validation is on: mock a response with a wrong type for a required field (string where a number is expected); assert `ResponseValidationError` with the raw body attached.
4. Run the type checker and the tests.

### Output
`response_validation`.

### Quality Gate
- Negative static test proves the checker runs on tests (an unused ignore or `@ts-expect-error` would fail).
- Forward compatibility test passes.

## Worked Example

Illustrative only. `stack = python`, pydantic v2 models, `UserStatus` enum `active | disabled`.

Phase 2 changes `status: UserStatus` to `status: Union[UserStatus, str]` with a docstring noting unknown values pass through.
```
$ mypy --strict acme_client
Success: no issues found in 48 source files
$ pytest tests/test_forward_compat.py -q
..                                                           [100%]
2 passed in 0.04s
```

---

## Exit Criteria

DONE when public methods return precise types under the strict checker, runtime validation is decided per the table, unknown fields and enum values never break a response, and tests prove both the types and forward compatibility.

---

## Error Handling

| Phase | Failure Mode | Response |
|---|---|---|
| Phase 1 | Strict mode floods errors in generated code | **Adjust**: run strict on the facade package and record generated-code errors separately; do not edit generated files. |
| Phase 2 | User wants strict rejection of unknown fields | **Return**: explain the forward compatibility rule; if they insist, record it as their decision. |
| Phase 3 | Negative test does not fail when broken | **Stop**: the checker is not running on the tests directory; fix the config. |
