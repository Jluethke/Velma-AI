# Lifecycle Launch Protocol

Launch the lifecycle system by classifying existing contacts, setting initial baselines, and running the first review cycle.

## Inputs

- `field-schema`: The contact record fields
- `view-definitions`: The filtered views

## Outputs

- `initial-classification`: Every contact classified into a lifecycle stage with the evidence for that classification
- `first-action-queue`: The immediate actions generated by the first run: contacts approaching decay, contacts that should be parked, and contacts whose stage assignment needs verification

## Process

1. Classify all existing contacts using the stage indicators. For each contact, find the last interaction date and the nature of the last few interactions. Assign the stage based on recency and behavior, not gut feeling. If you cannot find evidence for a stage, default to the lower one.
2. Flag contacts where the classification feels wrong. This is the calibration step. If someone you consider trusted got classified as acquaintance because you have not interacted in 200 days, either your decay window is too tight or the relationship actually is more dormant than you thought. Adjust the decay parameters based on these calibration cases.
3. Generate the first action queue: sort all contacts by decay deadline ascending. The ones closest to downgrading are your immediate priorities. Also flag any contacts already past their decay window who need to be formally downgraded or re-engaged.
4. Set the review cadence: commit to reviewing the approaching-decay view on a fixed schedule (daily for sales, weekly for personal). The system only works if you review it. A lifecycle engine that nobody checks is a database, not a system.
