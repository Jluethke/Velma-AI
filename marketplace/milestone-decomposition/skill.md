# Milestone Decomposition

Break the project into milestones where each milestone produces a working (if incomplete) version and exercises at least one hard part.

## Inputs

- `scoped-project`: The chosen project with scope boundaries
- `stretch-elements`: The aspects beyond current ability

## Outputs

- `milestone-plan`: 4-6 milestones, each producing a working version, each exercising at least one hard part of the skill
- `milestone-deliverables`: The specific, tangible output of each milestone that you can show to someone

## Process

1. Each milestone must produce something that works, even if it is rough. Milestone 1 should produce a working prototype in the first 3-5 days. Nothing kills learning faster than spending 3 weeks with nothing to show.
2. Order milestones so that the first milestone covers the most foundational hard part. If you fail at the foundation, you learn that early instead of late.
3. Each milestone after the first should add one hard part. By the final milestone, all stretch elements have been exercised.
4. Make each milestone's deliverable something you can share with another person for feedback. External feedback on a tangible artifact is the fastest way to calibrate your skill level.
