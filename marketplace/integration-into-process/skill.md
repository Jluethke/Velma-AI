# Integration Into Process

Integrate the lessons into the actual processes, checklists, and templates that the team uses. A lesson that lives only in a report will be forgotten.

## Inputs

- `lessons`: The extracted lessons
- `lesson-owners`: Who implements each lesson

## Outputs

- `process-changes`: Specific changes to existing processes, checklists, templates, or workflows that embed the lessons
- `verification-plan`: How to verify in the next project that the lessons were actually applied

## Process

1. For each lesson, identify the specific process, checklist, template, or workflow where it should be embedded. The lesson 'walk through 3 edge cases per spec section' becomes a checklist item on the spec template.
2. Make the change to the process document now, during the review. Do not create a separate action item to update the process later. If you leave the review without the change made, it will not happen.
3. Set up a verification trigger: at the start of the next similar project, check whether the process changes were followed. The trigger should be automatic (a checklist item, a meeting agenda point), not dependent on someone remembering.
4. Review the lessons from the previous AAR at the start of each new project to reinforce them. Lessons fade from memory within weeks if not actively reinforced.
