# Delegated Outcome Definer

For each delegated task, define the outcome rather than the process. Specifying the result and the boundaries, then leaving the method to the person, is what makes delegation develop people instead of creating remote-controlled hands.

## Inputs

- `task-person-matches`: The task-person matches
- `readiness-levels`: Each person's readiness

## Outputs

- `outcome-statements`: Each delegation written as an observable outcome rather than a list of steps
- `boundary-conditions`: The budget, deadlines, and decision limits for each delegated task

## Process

1. Write each delegation as an outcome: what good looks like when done, in observable terms, not a list of steps.
2. State the boundaries: budget, deadlines, decisions they can make alone, and decisions that need you.
3. Name the resources available to them, including who they can ask when stuck.
4. Confirm the outcome is specific enough that both of you would agree whether it was met.
