# Memory Maintenance Cycle

Establish the maintenance cycle that keeps institutional memory current. Stale documentation is worse than no documentation because it creates false confidence. Every document has a freshness date and an owner.

## Inputs

- `retrieval-architecture`: The retrieval system design
- `knowledge-navigation-map`: Navigation map across all knowledge layers

## Outputs

- `freshness-schedule`: Review schedule for all documentation: which documents, how often, who owns freshness
- `institutional-memory-system-doc`: Complete system documentation covering all three layers, capture methods, retrieval, and maintenance

## Process

1. Assign a freshness owner to every document. The owner is not necessarily the author. The owner is the person best positioned to know when the content becomes stale.
2. Set review cycles based on volatility: processes that change monthly get a 30-day review cycle. Stable policies get 180 days. Decisions get reviewed on their recorded review date.
3. The freshness review is a 5-minute check: is this still accurate? If yes, update the review date. If no, update the content or flag it for revision. If the process no longer exists, archive the document.
4. Track the freshness rate: what percentage of documents are within their review cycle? Below 80% means the maintenance process itself needs fixing.
