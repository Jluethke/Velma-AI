# Replacement Designer

Design the replacement behavior or belief that should take the old one's place.

## Inputs

- `pattern-origin`: When and why the pattern was learned
- `maintaining-conditions`: What keeps the pattern in place now

## Outputs

- `replacement-behavior`: The new behavior or belief in concrete terms
- `difference-notes`: How the new pattern differs from the old

## Process

1. Define the new behavior or belief in concrete terms.
2. Make sure the replacement meets the need the old pattern served.
3. Spell out how the new pattern differs in action from the old.
4. Check the replacement is specific enough to practice.
