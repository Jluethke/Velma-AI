# Process Freeze And Documentation

After the trial period, freeze the process: the minimal steps plus only the pain-driven additions become the new standard.

## Inputs

- `essential-steps`: The original minimal steps
- `added-back-steps`: Steps proved necessary by pain

## Outputs

- `final-process`: The frozen process: minimal steps + pain-driven additions, documented simply
- `process-rationale`: For each step: why it is in the process (which specific problem it prevents)

## Process

1. Combine the essential steps with the pain-driven additions. This is your new process.
2. Document it simply: one page maximum, with each step described in one sentence. If the documentation is longer than one page, the process is too complex.
3. Include the rationale for each step: 'This step exists because during the trial, problem X occurred 3 times when this step was not performed.' The rationale prevents blind removal later.
4. Communicate the new process to everyone who uses it. Emphasize that any suggested additions must go through the pain-driven protocol: propose the step, wait for the pain to appear, then add it if the pain proves it necessary.
