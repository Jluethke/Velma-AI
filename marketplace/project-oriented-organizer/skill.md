# Project Oriented Organizer

Organize captured items by active project, not by topic or category. A project is anything you are actively working on that has a deadline or a deliverable. Inactive projects get archived, not deleted.

## Inputs

- `capture-protocol`: The capture protocol defining what lands in the inbox
- `capture-friction-audit`: Verified capture paths

## Outputs

- `project-folder-structure`: The project-based folder structure with naming conventions and archival rules
- `inbox-processing-routine`: The routine for processing the inbox: move each item to a project folder or to the reference archive

## Process

1. List your active projects: anything with a deliverable and a timeline. These become the top-level folders. Add one folder called 'reference' for items that do not belong to a project but are worth keeping.
2. Define the inbox processing routine: once per day (or once per week), review each inbox item. Ask: does this relate to an active project? If yes, move it there. If no, move it to reference. If it is junk, delete it.
3. When a project completes, archive its folder. Do not delete. Archived projects become searchable reference material.
4. When a new project starts, create a folder. Pull relevant items from reference and other project archives into the new folder.
