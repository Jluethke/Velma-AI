# Host Unit Testing with Ceedling, Unity and CMock

**One-line description:** Runs firmware C modules as host-compiled unit tests with Ceedling, using Unity assertions and CMock-generated mocks of the hardware abstraction layer, with gcov coverage, and with rules that stop tests from being weakened to get a pass.

**Execution Pattern:** Phase Pipeline

---

## Inputs

- `project_dir` (string, required): Firmware source tree.
- `module_under_test` (string, required): One C module (for example `src/battery_monitor.c`) whose logic is tested on the host.

---

## Outputs

- `test_report` (object): Ceedling version, test counts (tested, passed, failed, ignored) copied from output, the coverage figure for the module, and the list of mocked headers.

---

## Phase 1: Set Up Ceedling

### Entry Criteria
- Ruby and a host C compiler (gcc or clang) installed: `ruby --version`, `gcc --version`.

### Actions
1. `gem install ceedling`, then `ceedling version` (record it; configuration keys differ between 0.31 and 1.x releases).
2. In `project_dir`, create a test project: `ceedling new <name>` in a scratch location and copy `project.yml` into `project_dir`, or follow the Ceedling docs for adding to an existing tree.
3. In `project.yml` set paths: `:paths: :test:` to `test/**`, `:source:` to the directory with `module_under_test`, `:include:` to the header directories. Enable the CMock mock prefix default (`mock_`) and add `gcov` to `:plugins: :enabled:`.
4. Run `ceedling test:all` once with no tests to confirm the toolchain works.

### Output
Working Ceedling project.

### Quality Gate
- `ceedling test:all` exits 0 and prints the test summary block.

---

## Phase 2: Design the Seam

### Entry Criteria
- Ceedling runs.

### Actions
1. List every header `module_under_test` includes. Classify:

| Header kind | Treatment |
|---|---|
| Hardware access layer (GPIO, ADC, I2C driver wrappers, HAL) | Mock: `#include "mock_<header>.h"` in the test |
| Pure logic module you also own | Real source, or mock if it pulls in hardware |
| Vendor device header with register structs | Do not mock; move register access behind your own wrapper header and mock the wrapper |
| `stdint.h`, `stdbool.h`, `string.h` | Real |

2. If the module touches registers directly (`GPIOA->ODR = ...`), first move that access into a small wrapper function in a separate file (one change, rebuild the target firmware to confirm it still links), then mock the wrapper.
3. Host types differ from target: `int` and pointer sizes may differ. Use fixed-width types (`uint32_t`) in the module.

### Output
Mock list.

### Quality Gate
- Every included header has a treatment row.
- Target firmware still builds after any wrapper extraction (build command exit 0 recorded).

---

## Phase 3: Write and Run Tests

### Entry Criteria
- Seam designed.

### Actions
1. Create `test/test_<module>.c` with `#include "unity.h"`, the module header, and `mock_` headers. Provide `setUp` and `tearDown`.
2. Write one test per behavior, starting with a failing test that states the expected behavior. Use typed assertions: `TEST_ASSERT_EQUAL_UINT16`, `TEST_ASSERT_EQUAL_HEX32`, `TEST_ASSERT_TRUE`, `TEST_ASSERT_EQUAL_MEMORY`.
3. Mock expectations generated by CMock for function `adc_read`: `adc_read_ExpectAndReturn(ch, value)`, `adc_read_IgnoreAndReturn(value)`; for void functions `gpio_write_Expect(pin, level)`. Arrays: `_ExpectWithArray`. Check the generated `build/test/mocks/mock_<header>.h` for exact names; do not invent functions.
4. Run: `ceedling test:<module>` for one module, `ceedling test:all` for everything. Read the summary: TESTED, PASSED, FAILED, IGNORED.
5. Coverage: `ceedling gcov:all`; read the line and branch percentages for `module_under_test`. Report the figure; do not invent a required threshold.
6. Rules: never delete, comment out, or `TEST_IGNORE()` a failing test to get green; never loosen an expected value to match buggy output; fix the code or record the failure.

### Output
`test_report`.

### Quality Gate
- Summary shows FAILED: 0 and IGNORED: 0 (copied verbatim), or each failure is recorded as an open defect.
- `git diff --stat test/` shows no deleted test functions compared with the previous commit.
- Coverage figure for the module recorded from gcov output.

## Worked Example

Illustrative. `module_under_test` = `src/battery_monitor.c`, which calls `adc_read()` from `adc_hal.h` and `gpio_write()` from `gpio_hal.h`.

- Phase 1: `ceedling version` prints the installed version; empty run passes.
- Phase 2: `adc_hal.h` and `gpio_hal.h` mocked; `battery_monitor.c` already uses only wrappers.
- Phase 3: test `test_low_voltage_turns_on_led` uses `adc_read_ExpectAndReturn(ADC_CH_VBAT, 1500); gpio_write_Expect(PIN_LED_LOW, 1); battery_monitor_poll();`. Output:
  ```
  TESTED:  6
  PASSED:  6
  FAILED:  0
  IGNORED: 0
  ```
  gcov reports line coverage for `battery_monitor.c`.

---

## Exit Criteria

DONE when the module's tests run on the host with zero failures and zero ignored tests, coverage is recorded, and no test was weakened.

---

## Error Handling

| Phase | Failure Mode | Response |
|---|---|---|
| Phase 1 | `ceedling` not found | **Adjust**: add the Ruby gem bin directory to PATH. |
| Phase 2 | Module includes a vendor register header | **Adjust**: extract a wrapper; do not mock the vendor header. |
| Phase 3 | "Called more times than expected" | **Adjust**: add the missing `_Expect` or correct the code under test; do not switch to `_Ignore` to hide it. |
| Phase 3 | Test fails | **Stop**: report the failure with output; fix code, never the assertion, unless the requirement itself changed. |
